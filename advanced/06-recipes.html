Recipes: six scripts

Six whole scripts, each one a feature. Paste one into 📜 Scripts, change the names at the top to yours, and press Play.

You'll learnhow the pieces of the earlier pages fit together in real features: waves of monsters with a countdown, a lift that follows a pressure plate, a shop panel, a day and night cycle, a checkpoint kept in a save game, and a score per player Time45 minutes Needspages 1 to 5 of this track; a module of your own, or Gem Hollow

Every recipe follows the same pattern:

  • Settings at the top, in capitals: the prop names, tags, sounds and numbers to change for your map.
  • Things are found late, the first time a hook needs them, because the map's props don't exist yet when your script loads.
  • Plain Lua 5.1, and only the engine functions from this track.

Paste each one as a script of its own in 📜 Scripts. Scripts don't see each other's local names, so two recipes never clash, and their hooks all run.

1. A wave arena with a countdown

What it does. A player crosses the arena's entrance. The HUD counts down five seconds, then a wave of monsters appears in the arena. When the last one dies, the next countdown starts. After three waves, the HUD says the arena is clear.

Where. 📜 Scripts, as arena.lua. In the map, give the arena room a tag (here 1) and flag its entrance wall trigger. Add a HUD text with {hud.arena} in ▣ Screens.

Notes.

  • on_cross fires for every wall flagged trigger. If the map has others, check side against your entrance's number, which print(side) tells you.
  • The script asks mobs.health rather than m:valid(), because a dead monster may leave its body behind.
  • Calling dnp.hud every tick is fine: only changes are sent.
  • Nothing here is saved. If the level is put back from a save in the middle of a wave, the arena starts again from idle. Wrap state and wave in dnp.persist if that matters to you.

2. A pressure plate lift

What it does. While anyone stands on a plate, a lift goes down. When nobody does, it comes back up, from wherever it got to. Step off halfway, and it turns round smoothly.

Where. 📜 Scripts, as plate.lua. You need a prop named plate (not solid, so players can stand in it) and a room tagged 7 for the lift.

Notes.

  • The script never asks the lift where it is. It works out its progress from the tick, the same way the engine moves it, so the next move starts exactly where the last one is.
  • fx.frac(-DROP * p, TRIP) is an exact fraction. A Lua division such as -DROP * p / TRIP would be a fraction the engine refuses.
  • <= 2 gives one tick of slack, so the plate doesn't flicker between pressed and not.
  • "floor" moves only the floor, so the ceiling above stays put.

3. A shop that sells health

What it does. Using the shopkeeper opens a panel with two potions. Each player starts with 50 gold, shown on their HUD. A potion costs gold and heals, never past full health.

Where. 📜 Scripts, as shop.lua. A usable prop for the shopkeeper; in Cinderfall, try vos. A HUD text with Gold {hud.gold} in ▣ Screens. The sounds are Gem Hollow's: use names from your own 🔊 Sounds.

-- shop.lua: a shopkeeper sells potions for gold.
local SHOPKEEPER = "shopkeeper"
local START_GOLD = 50
local SMALL_PRICE, SMALL_HEAL = 10, 25
local BIG_PRICE = 25                       -- the big one heals fully
local MAX_HP = (mobs and mobs.player_max_hp) or 100
local W_SMALL, W_BIG, W_LEAVE = 1, 2, 3

local gold = {}   -- player index -> gold
local shop = {}   -- player index -> the open panel's id

local function gold_of(e)
  local i = e:index()
  if gold[i] == nil then gold[i] = START_GOLD end
  return gold[i]
end

local function buy(e, price, heal)
  local hp = e:hp() or 0
  if hp >= MAX_HP then print("already at full health") return end
  if gold_of(e) < price then
    dnp.sound("ui.close", e)
    print("not enough gold")
    return
  end
  gold[e:index()] = gold_of(e) - price
  e:set_hp(math.min(MAX_HP, hp + heal))
  dnp.sound("pickup.heart", e)
  dnp.hud(e, { gold = gold[e:index()] })
  print("healed to " .. math.min(MAX_HP, hp + heal) .. ", gold left " .. gold[e:index()])
end

function on_prop_use(e, p)
  if p:name() ~= SHOPKEEPER or shop[e:index()] then return end
  dnp.hud(e, { gold = gold_of(e) })
  local ui = dnp.ui_open(e, { title = "Potions", widgets = {
    { kind = "label",  id = 4, label = "Prices are in gold." },
    { kind = "button", id = W_SMALL, label = "Small potion, +" .. SMALL_HEAL .. ": " .. SMALL_PRICE },
    { kind = "button", id = W_BIG, label = "Big potion, full health: " .. BIG_PRICE },
    { kind = "button", id = W_LEAVE, label = "Leave" },
  } })
  if ui ~= 0 then shop[e:index()] = ui end
end

function on_ui_event(e, ui_id, widget, value)
  if shop[e:index()] ~= ui_id then return end
  if widget == W_SMALL then
    buy(e, SMALL_PRICE, SMALL_HEAL)
  elseif widget == W_BIG then
    buy(e, BIG_PRICE, MAX_HP)
  elseif widget == W_LEAVE then
    dnp.ui_close(e, ui_id)
    shop[e:index()] = nil
  elseif widget == 0 then                  -- closed with its x
    shop[e:index()] = nil
  end
end

Notes.

  • The gold lives in this level only. Walk into another map and you start with 50 again. For gold that follows a player, keep it in a game graph and talk to it with dnp.call_game (page 5).
  • The panel's labels can't change while it is open, which is why the gold is on the HUD. A template's decor can show {hud.gold} inside the panel too.
  • A player's maximum health comes from mobs.player_max_hp when the module sets it, else 100.

4. Day and night

What it does. Every two minutes, the light of every outdoor room fades between day and night over 20 seconds. Rooms with a chosen tag, such as houses with their own lamps, keep their light.

Where. 📜 Scripts, as daynight.lua. Tag your indoor rooms 50, or change INDOOR_TAG.

-- daynight.lua: outdoor rooms fade between day and night.
local DAY, NIGHT = 220, 70          -- light levels, 0..255
local HALF_DAY = 2 * 60 * 60        -- ticks of day, then of night: 2 minutes
local FADE = 20                     -- seconds each change takes
local INDOOR_TAG = 50               -- rooms with this tag keep their own light

local outdoor = nil                 -- room numbers, found once
local next_at = 0
local is_day = true

local function outdoor_rooms()
  if outdoor == nil then
    outdoor = {}
    for _, s in ipairs(dnp.sectors()) do
      if s:tag() ~= INDOOR_TAG then outdoor[#outdoor + 1] = s:index() end
    end
  end
  return outdoor
end

function on_tick()
  local t = dnp.tick()
  if t < next_at then return end
  next_at = t + HALF_DAY
  local level = is_day and DAY or NIGHT
  for _, i in ipairs(outdoor_rooms()) do
    dnp.set_sector_light(i, level, FADE)
  end
  print((is_day and "day" or "night") .. " begins at tick " .. t)
  is_day = not is_day
end

To watch it turn quickly while you test, set HALF_DAY to 10 * 60: ten seconds.

Notes.

  • Each dnp.set_sector_light is one message to every player, sent once per change, and the fade is drawn by each game. Twice in four minutes is cheap even on a big map. Don't do it every tick.
  • It replaces the light you drew. A cave you made dark becomes as bright as day: tag it indoor.
  • The engine keeps room lights with the level, so a level put back from a save is lit as it was. The cycle itself starts again from day.
  • For a sky that changes too, call dnp.sky next to the lights (page 4).

5. A checkpoint that survives a save

What it does. Touching a flag makes it your checkpoint, with a sound. When you die, you come back at your last flag instead of the level's start. Save the game with F5, load it with F9, and your checkpoint is still yours.

Where. 📜 Scripts, as checkpoint.lua. Flag props named flag1 to flag3, and save and load games on in ⚙ Settings. Gem Hollow already does this with its checkpoints graph, so try it in a module of your own.

-- checkpoint.lua: touch a flag to make it where you come back.
local FLAGS = { flag1 = true, flag2 = true, flag3 = true }
local SOUND = "world.checkpoint"

local spot = {}   -- player index -> vec3

function on_touch(e, p)
  if e:kind() ~= 0 or not FLAGS[p:name()] then return end
  local here = p:pos()
  local old = spot[e:index()]
  if old == nil or old ~= here then          -- a new flag, not the same one again
    spot[e:index()] = here
    dnp.sound(SOUND, p)
    print("checkpoint for player " .. e:index())
  end
end

-- Coming back: the runtime sends a dead player home, then calls this.
if mobs then
  local before = mobs.on_player_death
  mobs.on_player_death = function(e, by)
    if before then before(e, by) end
    local at = spot[e:index()]
    if at then e:teleport(at) end            -- queued after the trip home, so it wins
  end
end

-- Kept in a save game, with the player.
dnp.persist_player("checkpoint", function(e)
  return { at = spot[e:index()] }            -- a vec3 is plain data
end, function(e, t)
  spot[e:index()] = t.at
end)

Notes.

  • on_touch fires every tick on the flag. Comparing positions makes the sound play once per new flag, not 60 times a second.
  • Two teleports in one tick: the last one wins. The runtime's trip home comes first, so yours is the one that sticks.
  • The checkpoint lives in this level and in save games. It does not follow the player to another map, and a level that restarts without a save forgets it. Add a dnp.persist part as well if the level should keep everyone's checkpoints when it unloads.
  • If another script sets mobs.on_player_hurt, it owns the whole death, and on_player_death may never be called.

6. A score per player

What it does. When a monster dies, the player who killed it scores points by the monster's kind. Each player's score is on their own HUD.

Where. 📜 Scripts, as score.lua: everything above the playground only line. A HUD text with Score {hud.score} in ▣ Screens. The kinds are Gem Hollow's monsters.

Notes.

  • Who killed a monster arrives in by, in more than one shape: a record with .e for a shot or a missile, or nil. (A script that hurts something can name the attacker: mobs.hurt(target, n, attacker) takes the entity and turns it into a record.) A player's melee swing passes nil, so the script also remembers who struck each monster last, in on_attack.
  • That on_attack only takes notes. It doesn't hurt anything, so it doesn't double your weapons' damage.
  • It keeps any mobs.on_death that was already there and calls it first.
  • The score is the level's. For a score over the whole game, send each kill on to a game graph: dnp.call_game("graph_call", "scored", POINTS[m.kind] or 1, p), and let the graph add it up.

Try one in the studio

  1. Open Gem Hollow from Home → ◆ examples. In 📜 Scripts, add score and paste recipe 6, without the playground part.

  2. In ▣ Screens, on the HUD tab, press + element… and add a text that reads Score {hud.score}. Drag it to a free corner.

  3. Play world and defeat a slime and a bee. The score shows 10, then 35.

  4. Open 📋 play log and find the scores; total lines.

  5. Change slime = 10 to slime = 100 and play again. Nothing else needs to change.

In recipe 2, why does the script keep its own p0 and t0?

  • To start each move exactly where the lift is, so it never jumps
  • Because move_parametric needs them as arguments
  • To save them in a save game

A move starts at its from. Working out the progress from the tick gives the lift's real position, even when it turns round halfway.

In recipe 1, you add a second wall flagged trigger elsewhere in the map. What goes wrong?

  • Nothing
  • The arena never starts
  • Crossing the other wall starts the arena too

on_cross fires for every trigger wall. Check the side argument against your entrance's number.

In recipe 3, a player buys a potion in one map, then walks into the next. How much gold do they have there?

  • What they had left
  • 50: each level's script has its own gold table
  • None

A 📜 script runs separately in every level. Gold that follows the player belongs to a game graph.
