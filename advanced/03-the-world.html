Touching the world

A level is three kinds of thing: entities that move and think, props that sit, and rooms. This page shows how to find each one from Lua, read it, and change it.

You'll learnthe methods of entities, props and rooms, how to find a room by its tag, lights, textures and weather, moving rooms with move_parametric, spawning monsters and props, hurting, swinging and noticing deaths, line of sight and reach, and sound, music, particles and trails Time40 minutes NeedsEvents and time; the example Gem Hollow

Entities

An entity is a body that moves: a player or a monster. dnp.players() lists the players, dnp.entities() lists every entity, and dnp.entity(i) gets one by its index. A player's e:kind() is 0.

MethodGives or does
e:valid()whether the handle still names something
e:pos(), e:vel()position and velocity, as vec3
e:grounded()standing on something
e:sector()the room it stands in, as a number (-1 in a neighbouring map of the same world)
e:index(), e:player()its slot in this level; a player's number that stays the same between levels
e:kind(), e:name()its catalogue number and name (a monster's slime; nil for a player)
e:facing()which way it faces, in brad: a full turn is 4294967296
e:hp(), e:set_hp(n)a player's health. For monsters use mobs.health (below)
e:buttons(), e:actions()the buttons held this tick, and the module's own keys held
e:teleport(v), e:set_velocity(v), e:add_impulse(v)move it. Queued (page 2)
e:set_animation(n), e:set_solid(b)its picture's state number; whether things bump into it
e:param(name), e:add_effect(name, op, value[, ticks]), e:remove_effect(id)read and change a movement rule (move_speed, jump_impulse, gravity_scale …). op is "mul", "add" or "set". add_effect returns an id
e:change_map([level[, spawn_tag]])send a player to another map (page 5)

An effect is how you change a rule for a while. This doubles a player's speed for five seconds, then lets it lapse by itself:

e:add_effect("move_speed", "mul", 2, 300)   -- 300 ticks = 5 seconds

Without ticks, an effect lasts until you remove it with the id it returned. Keep the id if you will want to undo it.

e:teleport puts the body where you say, even inside a wall. Before you move something, ask dnp.place(pos, radius, height[, ignore]) whether a body that size fits there: it gives back the spot on the floor, or nil when a wall, a low ceiling or another body is in the way. Pass the body you are moving as ignore, so it does not count against itself.

local spot = dnp.place(vec3.new(12, 4, 0), fx.frac(1, 2), 2, e)
if spot then e:teleport(spot) end

Props

A prop is a body without a brain: a lever, a coin, a crate. dnp.props() lists them and dnp.prop(i) gets one. A prop's p:name() is the name it has in Props. Finding by name is the robust way:

local function find_prop(name)
  for _, p in ipairs(dnp.props()) do
    if p:name() == name then return p end
  end
  return nil
end
MethodGives or does
p:valid(), p:index(), p:kind(), p:name()as for entities
p:pos(), p:set_pos(v)where it is; move it
p:solid(), p:set_solid(b)whether it blocks
p:set_facing(brad)turn it
p:set_animation(n)its state number from the sprite: Gem Hollow's levers have 0 off and 1 pull
p:despawn()remove it

Rooms (sectors)

The engine calls a room a sector. Each has a number (its index) and the tag you gave it in the map editor. Many rooms can share a tag. Look rooms up by tag, once, and keep the list:

local function rooms_tagged(tag)
  local out = {}
  for _, s in ipairs(dnp.sectors()) do
    if s:tag() == tag then out[#out + 1] = s end
  end
  return out
end

dnp.sectors() builds a table of every room, which costs something on a big map. Call it once, not every tick. dnp.sector(i) gets one room by number.

MethodGives or does
s:index(), s:tag()its number and its tag

s:center()a point in the middle of its floor, as vec3
s:offset()how far it has moved from where you drew it
s:neighbors()the rooms next to it
s:move_parametric(…)move it smoothly (below)

Lights, textures and weather

These take the room's number, so pass s:index():

dnp.set_sector_light(s:index(), 60, 2)              -- 0..255, fading over 2 seconds
dnp.set_sector_texture(s:index(), "floor", "LAVA1")   -- or "ceiling"
dnp.set_sector_effect(s:index(), "fog", { density = 0.5, color = "#203040" })
dnp.set_sector_effect(s:index(), "snow")             -- rain, snow, dust, embers, fog
dnp.set_sector_effect(s:index(), "snow", false)      -- stop it

A wall's picture is dnp.set_side_texture(side, "upper"|"middle"|"lower", NAME). Texture names are the ones in Textures. Every one of these is kept by the server, saved with the level, and sent to players who arrive later.

Moving rooms: move_parametric

Doors, lifts, rafts and spinning platforms are rooms that move. move_parametric gives a room a whole motion at once:

s:move_parametric(from, to, ticks [, mode [, part [, spin_degrees [, pivot]]]])
ArgumentMeaning
from, tovec3 offsets from where you drew the room. vec3.new(0, 0, -4) is 4 units down
tickshow long one trip takes
mode"once" (stays at to; the default), "loop" (jumps back and repeats) or "pingpong" (there and back, for ever)
part"both" (the default), "floor" or "ceiling"
spin_degrees, pivotturn the room by that much over the same time, about its middle or about pivot

The motion is worked out from the tick on every machine, so it is smooth and costs no network traffic while it runs. It returns false if the map already has too many moving rooms.

door:move_parametric(vec3.new(0, 0, 0), vec3.new(0, 0, 4), 60, "once", "ceiling")  -- a door opens
lift:move_parametric(vec3.new(0, 0, 0), vec3.new(0, 0, -3), 120, "once", "floor")  -- a lift goes down
raft:move_parametric(vec3.new(0, 0, 0), vec3.new(8, 0, 0), 240, "pingpong")        -- a raft sails
wheel:move_parametric(vec3.new(0, 0, 0), vec3.new(0, 0, 0), 480, "loop", "both", 360) -- a wheel turns

from is where the move starts, so a second move should start where the first one ended. Otherwise the room jumps. s:offset() tells you where it is now. s:set_offset(v) places a room by hand, but it sends a message every time, so keep it for rare jumps, not for animation.

Spawning

A monster comes from the mob runtime, so it gets its brain and its health:

local m = mobs.spawn("slime", vec3.new(12, 4, 0))
local sleeper = mobs.spawn("bee", where, { dormant = true })  -- placed asleep, as the Place tool's dormant does

The kind is the monster's name in Monsters. mobs.has("slime") says whether the module has it. A prop comes from dnp.spawn_prop(name, pos), with the name from Props. Both return the new handle, or nil and a line in the log.

A level that is being put back from a save holds back what its scripts spawn while they load. Spawning later, in a hook, is not held back, and is not saved either unless you save it yourself. See Restoring.

Hits and deaths

on_attack(attacker, target) says that a swing reached something. What it costs is up to the scripts. If your module has weapons, the weapons runtime already answers it, so don't hurt the target a second time.

FunctionDoes
mobs.hurt(target, amount, by)hurt a monster or a player, through the monsters' own rules: pain, death, loot, graphs' when_hurt. by may be the attacking entity itself, mobs.hurt(target, 10, e): you no longer need mobs.synthetic_owner to make a record of it
e:swing()start a swing now, in the shape the body's attack settings hold, for a monster or a player. A newer swing replaces one still sweeping; inside the last one's cooldown nothing happens. What it reaches comes to on_attack, as with any swing
mobs.health(e), mobs.set_health(e, hp)a monster's health; nil for anything that is not a living monster here
mobs.on_death = function(m, by) … endyours to set: called when a monster dies. m.e is its entity, m.kind its kind
mobs.on_player_death = function(e, by) … endcalled after a player dies and is sent home

Another script may have set mobs.on_death already. Keep the old one and call it, so both run:

local before = mobs.on_death
mobs.on_death = function(m, by)
  if before then before(m, by) end
  print(m.kind .. " died")
end

by is whoever did it: a record with .e for a monster or a weapon, the attacker's entity when a script passed one, or nil. Recipe 6 shows how to get a player out of it.

Line of sight

dnp.can_see(a, b) is true when nothing stands between two entities' eyes. dnp.can_reach(a, b) asks the same for a blow struck at arm's length: no wall or shut door between them (a ledge does not count). A monster's melee asks it, so check it before your own script hurts what stands in front of a. dnp.hitscan(e, range[, spread[, slope]]) fires an instant ray along e's facing and returns what it hit (or nil) and where the ray ended. dnp.find_path(from_sector, to_sector) finds a route between rooms, but a level gets only 64 route searches a tick, shared with its monsters. When it says nil, "path budget", try again next tick.

Sound, music and particles

dnp.sound("world.lever", p)                         -- from a prop, following it
dnp.sound("world.secret", e:pos())                  -- from a point
dnp.music(nil, "boss", 800, "next_bar")              -- everyone here: cue, fade in ms, when
dnp.music(e, "default")                              -- one player
dnp.vfx(3, e:pos())                                  -- particle kind 3
e:set_trail(3)                                       -- kind 3 follows e
e:set_trail(0)                                       -- and stops
  • Sound names are the ones in Sounds. A name the pack doesn't have is silent.
  • Music cues are the map's cues in Music. The last argument is "next_bar", "loop_end" or "now".
  • A particle kind is the number shown in Particles.
  • e:set_trail(kind) and p:set_trail(kind) hang a trail on a body: the particle kind follows it until you set it back to 0 or the body goes. An aura on a monster, smoke behind a prop. It is not saved, so set it again when the level loads.

Try it in the studio

  1. Open Gem Hollow from Home → examples. In Maps, open world and tap the red gate with Select. Its tag is 11.

  2. In Scripts, add a script called world. Write an on_prop_use that, for the prop named lever_blue, finds the rooms tagged 900 (the water) and calls dnp.set_sector_light(s:index(), 40, 3) on each.

  3. In the same hook, play world.secret at the lever with dnp.sound.

  4. Press Play, find the blue lever and use it. The water darkens over three seconds.

  5. Change 40, 3 to 40, 0 and play again. The change is instant now.

A lift is at vec3.new(0, 0, -3) after a "once" move down. You call lift:move_parametric(vec3.new(0, 0, 0), vec3.new(0, 0, -3), 120, "once", "floor") again. What happens?

  • Nothing: it is already there
  • It jumps back up to where it was drawn, and goes down again
  • It goes 3 more units down

from and to are offsets from where the room was drawn, and the move starts at from. Start the next move where the last one ended.

Which is the right way to read a slime's health?

  • mobs.health(e)
  • e:hp()
  • dnp.health(e)

A monster's health belongs to the mob runtime. e:hp() is a player's.

Your new script sets mobs.on_death = function(m, by) … end, and an older script's kill counter stops counting. What should you have done?

  • Used on_attack instead
  • Nothing: two handlers can't both run
  • Kept the old mobs.on_death and called it from yours

There is one mobs.on_death per level. Setting it replaces whatever was there, so keep the old one and call it too. (Graphs' when_dies are told separately, so they keep working either way.)
