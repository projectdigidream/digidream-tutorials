Lua in the studio

Graphs and triggers say most things. When they can't, you write Lua. This page shows where Lua goes in the studio, when it runs, and how to read what it says back.

You'll learnthe three places Lua lives, which Lua machine runs each one and in what order, how to write and test a first script, how errors look in the Play log, and the Lua 5.1 and fixed-point rules that trip people up Time30 minutes NeedsDigidream Studio (Get the tools), the example Gem Hollow, opened from Home; it helps to have read Graphs and Thinking in graphs

This track is for people who already know a little Lua, or are happy to learn it as they go. You don't need to know any other programming language. Every example runs on the engine the studio ships, and many of them also run right here on the page.

📜 Scripts

+ script asks for a file name. It suggests module_hooks.lua. The new script starts with one line:

-- Runs in every level of the module, after its monsters are loaded.

Tap a script in the list to edit it in the text box. Below it are rename and delete. With the Code plugin on, you also get ✎ edit in Code and open with…. Code is a real Lua editor: line numbers, colours, and a warning when a block is never closed. See Plugins.

Each script has its own scope. The studio wraps it in do … end, so a local in one script is invisible to the others. A hook such as on_tick must be a global function: write function on_tick(), never local function on_tick(). If two scripts both define on_tick, both run, one after the other.

Extra Lua

In the map editor, open ⋯ More → Map settings…. The extra Lua box is kept exactly as you type it. It goes at the very top of the file the studio writes for that map. The same sheet shows how many of the map's script slots are used.

The lua action

In a graph, an action node set to do lua runs one line of Lua when the run reaches it. The line sees one value, ev: the event that started the run.

FieldWhat it holds
ev.entitywho did it: the player who pressed, touched or crossed
ev.targetwhat it was done to: the prop used or touched, the thing hit
ev.side, ev.sectorthe wall and the room, for wall and line events
ev.ui_id, ev.widget_id, ev.valuefor panel events
ev.crush_kindfor a crush: "vertical" or "pinned"

A one-liner can call a global function from your 📜 script. The graph does the "when", and your script does the hard part:

give_bonus(ev.entity)

The studio stores the line as text, and the server compiles it when the level loads. A server that runs in its strict trust profile removes the compiler, and then refuses the line. If your module will be hosted that way, keep your Lua in 📜 Scripts. More in Lua or graphs.

Which Lua runs them, and when

Every level has its own Lua machine. Nothing is shared between levels: not a variable, not a table. A level's machine starts when the level loads and is thrown away when it unloads.

So a 📜 script runs once per level, not once for the game. In a module with three maps there are three copies of your script, each with its own variables. When a level starts again, your script starts again from its first line.

When a level loads, its scripts run in this order:

  1. The engine's runtimes the map needs: monsters, triggers, graphs. Then the map's own graphs.
  2. Your 📜 scripts, one after another, after the module's monster definitions.
  3. The map's own file: first its extra Lua, then its camera, the props and monsters you placed, and its triggers.

At load, the map's things don't exist yet. The top of a 📜 script runs before the map places its props and monsters. So dnp.props() finds nothing there. Look things up later, inside a hook, the first time you need them. Every example in this track does it that way.

There is also one game machine, which runs once for the whole server. The studio writes what runs there for you: the weapons, the player's sounds and the game's graphs. The studio has no editor for hand-written game-wide Lua. For game-wide logic, use a game graph (The game graph, calls and maps). Your level scripts can still reach it, as page 5 shows.

In Cinderfall nine maps are walked as one world. Each map is still its own level with its own Lua machine, so your script runs nine times, side by side. A player standing in the next district shows up in dnp.players() with e:sector() equal to -1. Events and time shows how to skip them.

Your first script

This script says hello when its level starts. Then, when a player uses a prop, it names the prop and plays Gem Hollow's lever sound on it.

Press use in the playground to fire on_prop_use with the toy level's lever. Now do it for real:

  1. On Home, open ◆ examples and choose Gem Hollow.

  2. Open 📜 Scripts. Gem Hollow has none: it does everything with graphs. Press + script and type hello. The studio adds .lua.

  3. Paste the script above into the text box, under the first comment line. Tap outside the box so the studio keeps the change.

  4. Open 🗺 Maps, open world, and press ▶ Play.

  5. Walk to a lever and press use (E). The first time, you hear the lever sound twice: once from the levers graph, and once from your script.

  6. Come back with ◀ Studio. On Home, open 📋 play log and scroll to play-server.log. Find your two lines. They start with [lua: and the name of the file the studio wrote your scripts into, module.lua.

  7. Back in 📜 Scripts, change p:name() to p:nme(), play again and use the lever. Then read the Play log again. The error is at the top, under ✖ what looks wrong.

A player has no catalogue name, so the script prints e:index(), the player's slot number in the level. e:name() answers for monsters, and is nil for a player.

How errors look

Every line Lua prints, and every error, goes into play-server.log. The Play log page shows lines that look like failures first, in red. The shapes to know:

You seeIt meansWhat happens
[lua:…/module.lua] hello from level 1your printnothing; it is just a message
[srv] …/world.dnpm asked for …/module.lua and it failed: …module.lua:41: 'end' expected …the script could not load: a typo, or an error at its top levelthe level does not load, and the Play log opens by itself
[lua] on_prop_use error (tick 2210): …module.lua:47: attempt to call method 'nme' (a nil value)a hook failed while it ranthat call stops; the level carries on. The line repeats at most every 300 ticks
instruction budget exceeded in '…'a hook ran far too long, usually an endless loopthe call is stopped (see budgets)

Line numbers count lines in module.lua, not in your script. The studio puts the monster definitions and your other scripts in the same file, so line 47 there may be line 5 of yours. Look for the function name and the message, not the number.

Lua 5.1 and fx on one screen

The engine runs LuaJIT, which speaks Lua 5.1. Most tutorials on the web teach Lua 5.3 or 5.4. These are the differences that matter:

Instead of (5.3+)Write (5.1)
a // bmath.floor(a / b)
utf8.len(s)there is no utf8 library; #s counts bytes
a & b, a | bno bit operators; test one button with math.floor(b / dnp.button.USE) % 2 == 1
table.unpack(t)avoid it; index the table instead
gotoavoid it; use a flag or a function

Numbers are plain Lua numbers, and whole numbers are exact. The world itself uses fx, a fixed-point number that is the same on every machine. Positions, heights and speeds are fx.

local a = fx.int(3)          -- 3
local b = fx.frac(1, 4)      -- 0.25, exactly
local c = fx.parse("2.5")    -- 2.5, exactly
local d = fx.approx(0.1)     -- about 0.1: the one rounding door
local up = vec3.new(0, 0, c) -- x, y, z; any part may be fx or a whole number

local p = e:pos()            -- a vec3 of fx
print(p.z + 2)               -- fx plus a whole number works; prints like "4.500000"
print(p.z.int)               -- the whole part, rounded down
if p.z < fx.int(10) then end -- compare fx with fx

In Lua 5.1, p.z < 10 is an error ("attempt to compare"), and p.z == 10 is always false. Turn the number into fx first: fx.int(10). And never pass a fraction such as 0.5 where the engine wants fx. It refuses it and tells you to use fx.frac or fx.parse.

The playgrounds on this site run Lua 5.3 in your browser, against a toy level. Code written to the 5.1 rules above runs in both.

Your module has three maps, and one 📜 script with local count = 0 at the top. How many count variables exist while all three levels are loaded?

  • One, shared by the whole game
  • One per player
  • Three: one in each level

A 📜 script runs once in every level, and each level has its own Lua machine. Game-wide values belong in a game graph.

At the top of your script, outside any function, for _, p in ipairs(dnp.props()) do … end finds none of the map's props. Why?

  • Your scripts run before the map places its props
  • dnp.props() only works in the game machine
  • Props need dnp.restoring() to be true

The map's own file runs last, and it places the props. Look them up inside a hook instead.

The Play log says [lua] on_tick error (tick 900): …module.lua:212: attempt to index a nil value. Your script is 30 lines long. What do you do?

  • Nothing: line 212 is in another module
  • Look in your on_tick for something that can be nil; 212 counts lines of the whole generated file
  • Delete the monsters, which are on line 212

All 📜 scripts and the monster definitions share one file, so the number is not yours. The hook's name and the message point you to the place.
