Panels, HUD and camera

Everything a player sees on top of the world can come from Lua: a panel with buttons, a number on the HUD, the camera, a fade to black and the sky.

You'll learnhow to open, update and close a panel and answer it in on_ui_event, how to give it a designed look, how HUD values reach the screen, how to set one player's camera or every newcomer's, fades and letterbox bars, and the level's sky Time35 minutes NeedsEvents and time; it helps to know Sky, screens and weather

Panels

A panel is a small window over the game, shown to one player. You describe it as a table, and the engine draws it with the module's look.

local ui = dnp.ui_open(e, {
  title = "Travel",
  widgets = {
    { kind = "label",  id = 1, label = "Where to?" },
    { kind = "select", id = 2, label = "Place", options = { "North", "East" }, value = 0 },
    { kind = "slider", id = 3, label = "Delay", lo = 0, hi = 5, value = 0 },
    { kind = "toggle", id = 4, label = "Bring a friend", value = 0 },
    { kind = "button", id = 5, label = "Go" },
  },
})
  • Five kinds of widget: label, button, slider (whole numbers from lo to hi), select (a list of options) and toggle (0 or 1). A panel holds up to 32.
  • id is your own number, from 1. It comes back to you when the player uses the widget. Give each widget a different one.
  • ui_open returns the panel's id. Keep it: you need it to change or close the panel. It is 0 when nobody is there to see it.
  • pinned = true in the table leaves out the ×, so the panel stays until your script closes it.
FunctionDoes
dnp.ui_set(e, ui, id, value)changes one widget's value: a toggle's 0 or 1, a slider's position, a select's choice. A label has no value
dnp.ui_show(e, ui, id, shown)hides or shows one widget, which keeps its value
dnp.ui_close(e, ui)closes it

Answering: on_ui_event

When the player uses a widget, the engine calls on_ui_event(e, ui_id, widget_id, value) in the level that opened the panel.

  • value is the toggle's 0 or 1, the slider's number, or the select's choice counting from 0.
  • When the player closes the panel with its ×, you get widget_id 0.
  • Check ui_id. Another script's panel calls the same hook.

A whole panel: a lever that travels

Using the lever opens a travel panel. The player picks a room and presses Go. The script teleports them to the middle of that room and closes the panel.

Press use to open it.

Note the + 1. A select answers 0 for its first option, and Lua lists start at 1.

A panel opened by a level script closes when the player leaves the level. A label's text can't change once the panel is open. For text that changes, such as gold or a timer, use a HUD value, as below.

A designed look: template

Without more, a panel is drawn plainly, its widgets stacked. To place them and dress the panel, design a template: in ▣ Screens, the templates tab, + template and + slot. Each slot names one of your widget ids. Then open the panel with its name:

dnp.ui_open(e, { template = "travel", title = "Travel", widgets = { … } })

A template name is up to 24 of a-z, 0-9 and _. A widget no slot names is still drawn, stacked below. A template's decor can show HUD values, such as {hud.gold}, which is how a panel's text changes.

The panels you design in ▢ Panels are for graphs, which open them by name with open_panel. A script answers only the panels it opened itself.

HUD values

dnp.hud sends named values to the HUD of one player, or of everyone in the level with nil:

dnp.hud(e,   { gold = 35, quest = "Find the fuse" })
dnp.hud(nil, { countdown = 10 })
dnp.hud(nil, { countdown = false })   -- false clears it
  • A value is a whole number, a short string, or false. An fx is refused: send v.int.
  • A name is a-z, 0-9 and _.
  • Values are sent only when they change, so calling it every tick costs little.

A value shows only where an element is bound to it. In ▣ Screens, on the HUD tab, press + element… and add a text whose words include {hud.gold}, or a number or bar bound to hud.gold. The game graph's set_hud node writes the same values, so a graph and a script can share one HUD.

Markers

A marker is a small piece of UI hung on something in the world rather than on the screen: a bar over a monster, a sign over a door, a pointer over a goal. dnp.mark hangs one on an entity, a prop or a place (a vec3), drawn from a template (health, label, marker or debug_health), and gives back its id:

-- lever: a prop of the level, found with dnp.props()
local sign = dnp.mark(lever, 'label', { text = 'EXIT' }, { height = fx.frac(1, 2), range = fx.int(20) })
dnp.mark_set(sign, { text = 'OPEN' })
dnp.unmark(sign)

Markers are not saved, so hang them again as the level loads. The templates, the options (to, height, range, through_walls, debug) and the graph nodes that do the same are in Markers: health bars, signs, pointers.

The camera

dnp.camera(e, { … }) changes how one player's camera follows them. Give only the fields you want to change.

FieldUnitMeaning
distanceunitshow far behind
pitchturnshow far above, as a part of a full turn: 0.125 is 45°
yawturnswhere the camera stands around the player
lock_yaw, lock_zoom1 or 0stop the player turning or zooming
smoothing, leadhow fast it catches up; how far ahead it looks
cam_shake, cam_shake_timeunits, secondsa shake: it happens each time you send cam_shake
cam_mode, cam_path, cam_path_speed0 follow, 1 track, 2 flythrough, 3 auto, along the camera path with that tag
 
dnp.camera(e, { distance = 30, pitch = 0.2, lock_yaw = 1 })   -- a high, fixed view
dnp.camera(e, { cam_shake = 0.6, cam_shake_time = 0.5 })      -- a jolt

dnp.level_camera{ … } takes the same fields and sets the camera for everyone who joins the level. The map's own 🎥 Camera settings are written the same way, after your scripts, so they win. To change the view for a player who is already here, use dnp.camera.

Fades and letterbox

dnp.screen(e,   { fade = 1, fade_ms = 600 })            -- to black over 0.6 s
dnp.screen(e,   { fade = 0, fade_ms = 600 })            -- and back
dnp.screen(nil, { letterbox = 0.12, letterbox_ms = 400 }) -- bars for everyone here
dnp.screen(nil, { letterbox = 0 })

fade goes from 0 (clear) to 1 (black). letterbox is the height of each bar, as a part of the screen. Like the camera, give only the fields you change.

The list of steps is a small, general tool: each step has a tick and a function, and on_tick runs the ones whose time has come.

The sky

dnp.sky changes this level's sky for everyone, now and later. It takes the same words as a sky in 🌌 Sky:

dnp.sky("strip SKYHILLS repeat 2")   -- Gem Hollow's own picture, twice round
dnp.sky(nil)                         -- back to the module's sky

The level keeps it, and saves it with its state.

  • HUD values must be strings
  • dnp.hud only works in the game machine
