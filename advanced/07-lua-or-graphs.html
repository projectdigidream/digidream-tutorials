Lua or graphs, and debugging

Graphs and Lua run side by side in every level. This page helps you pick the right one for each job, join them, keep scripts fast, and find out why a script does nothing.

Which one?

Start with a graph. A graph is checked by the studio as you draw it, shows you what it does at a glance, and needs no typing. Reach for Lua when the graph would be long and awkward, or can't say it at all.

Mixing them

The best split is often: the graph decides when, Lua decides how. The graph listens for the event and checks the conditions, where you can see them. A one-line do lua hands the hard part to a function in your 📜 script.

-- In 📜 Scripts: a global function, so the graph can call it.
function push_away_all(from, strength)
  if from == nil or not from:valid() then return end
  local c = from:pos()
  for _, e in ipairs(dnp.entities()) do
    if e:kind() ~= 0 and e:valid() then
      local p = e:pos()
      local dx, dy = p.x - c.x, p.y - c.y
      if dx * dx + dy * dy < fx.int(100) then          -- within 10 units
        e:add_impulse(vec3.new(dx * strength, dy * strength, 2))
      end
    end
  end
end

In the graph: when_prop_used → once → an action node, do lua, with the line push_away_all(ev.entity, 3).

The other way round, a script starts a graph's on_call nodes with graphs.call("name", e, value), or a game graph's with dnp.call_game("graph_call", "name", value, e) (page 5).

The do lua line, and strict trust

  • In the studio the code field is one line. Put more than a call or two in a 📜 script, and call it.
  • The line is compiled when the level loads, so a typo is reported at load, naming the graph, not the first time someone pulls the lever.
  • It returns nothing, normally. If it returns false, the action counts as "did nothing", which matters to a once after it: a once isn't spent by an action that did nothing.
  • It isn't protected. An error in it shows in the Play log as an error of the hook that started the run, and the run stops there.
  • A server running in its strict trust profile has no Lua compiler, so it refuses a graph or trigger with a do lua line at load. 📜 Scripts are files, not text compiled at run time, and still run there. If your game may be hosted that way, keep all Lua in 📜 Scripts.

Keeping scripts fast

A level does all its work, Lua included, in about 16 ms a tick. The engine stops a hook after 2,000,000 instructions, a level's scripts after 8,000,000 in a tick, and warns when Lua takes more than 4 ms of a tick. You will rarely hit the limits. You will sometimes hit the warning. What usually causes it:

CostlyInstead
Work in on_touch, which runs every tick per touching pairnote the tick, and act when a touch starts (page 2)
dnp.sectors(), dnp.props() or dnp.entities() every tick: each builds a new tablelook rooms up once and keep them; dnp.player_count() builds nothing
dnp.find_path for many things at oncea level gets 64 route searches a tick, shared with its monsters; spread them over ticks
s:set_offset every tick to animate a roommove_parametric, which costs nothing while it runs
Sending the same value again and againremember what you sent, and send changes only
print in on_tick: 60 lines a secondprint when something changes

The warning names the slowest hook: [lua] tick N: … us in callbacks (worst … us in …). Look there first.

When a script does nothing

  1. Did it load? Open 📋 play log. A script that fails to load stops the level, and the log says asked for … module.lua and it failed, with the reason.
  2. Does the hook run? Put print("on_prop_use", dnp.tick()) as its first line. No line at all? Check the name, and that it is not local function.
  3. Is it the thing you think? Print p:name(), e:kind(), s:tag() before the if that tests them. Names are case-sensitive.
  4. Is something nil? Something looked up at load, before the map placed it; or a handle gone stale. Check valid().
  5. Read the red lines. ✖ what looks wrong lists every line with words such as error, failed, missing or not found. Start your own warnings with such a word, as in print("plate: missing room tagged 7"), and they are listed there too.
  6. Where am I? The debug overlay (in ⚙ Settings, when I press Play → always show it) shows the tick and your position as you play.
  7. Is another script in the way? A second script that replaces mobs.on_death, or a graph that does the same thing first. Comment out the other one and try again.

Practise on a broken script

  1. Open Gem Hollow from Home → ◆ examples. In 📜 Scripts, add broken with this, which has three mistakes:

    local function on_prop_use(e, p)
  print("used " .. p:nam())
  if e:pos().z < 0 then print("below the ground") end
end

  2. Play world and use a lever. Come back and open 📋 play log. Your script printed nothing, and there is no error either. The hook never ran: it is local. Remove the word local.

  3. Play again. Now the log has [lua] on_prop_use error … attempt to call method 'nam' (a nil value). Fix it to p:name().

  4. Play again. The next error says the script tried to compare two different types. e:pos().z is fx and 0 is a Lua number. Write fx.int(0).

  5. Play once more. The log shows used lever_red (or the lever you chose), and no errors. Delete the script when you are done.

Each player should have their own count of secrets found in a level. Graph or Lua?

  • A graph variable
  • Lua, with a table keyed by player
  • A trigger counter

A graph's variables and a trigger's counters are one value for the whole level. A table keyed by e:index() holds one per player.

Your module will run on a server in its strict trust profile. What still works?

  • Graphs with a do lua line
  • A trigger's lua action with code typed in
  • Your 📜 Scripts

Strict trust removes the compiler that text code needs, so do lua lines are refused at load. Script files still run.

The log keeps warning [lua] tick …: … us in callbacks (worst … in on_touch). What is the likely fix?

  • Do the work only when a touch starts, not every tick of it
  • Wrap on_touch in pcall
  • Move the code to on_post_tick

on_touch runs every tick for every pair touching. The warning names it as the slowest hook, so make it do less.
