Sync with GitHub

The studio keeps your modules on the device you made them on. Sync puts them in a GitHub repository of your own as well, so you can carry on on another device, go back to any earlier version, and never lose a module with a lost phone.

You'll learnhow to make a token, choose or create a repository, what syncs and when, what happens when two devices change the same thing, how to bring a module to a new device, and how to stop Time20 minutes Needsthe studio 0.3.2 or later (Get the tools), a free GitHub account, and an internet connection

What it is for

  • Several devices. Draw a map on your computer, test it on your phone on the bus, and come back to the computer with the phone's changes already there.
  • A history. Each sync is a commit on GitHub: a saved version with a date and a note. GitHub keeps every one of them.
  • A backup. If the device breaks or the app is removed, your modules are still in the repository.

There is no Digidream server in between. The Sync page talks to GitHub directly, from your device, with a key you give it (a token). Nothing goes anywhere else.

Sync is a bundled plugin: GitHub sync. It adds 🔄 Sync to the rail, and a service that runs in the background while the studio is open. See Plugins for what that means.

What you need from GitHub

An account

If you don't have one, go to github.com and sign up. A free account is enough. GitHub will ask you to confirm your email address.

A repository

A repository is a folder on GitHub with a history. All your modules go into one repository, one folder per module. Make it private, so only you can see it. You can create it from the Sync page (if your token allows it) or on GitHub first.

A token

A token is a long password that lets the studio act for you on GitHub, and only in the ways you allow. GitHub calls it a fine-grained personal access token; it starts with github_pat_. You can make one in two ways, and the Sync page tells you both:

The token can seeRepository accessPermissionsWhat the Sync page can do
All your repositoriesAll repositoriesContents: Read and write, and Administration: Read and writelist your repositories, and create a new one for you
One repository onlyOnly select repositories, and pick itContents: Read and writeuse that repository; it cannot create one. Make the repository on GitHub first.

One repository only is the safer choice. If the token ever leaks, it opens just that one repository, not everything you have on GitHub. The page's link make the repository on GitHub opens GitHub's new-repository form already filled in: named digidream-modules, private.

GitHub also asks for an expiration. When the token expires, sync stops until you give it a new one (see When something goes wrong). Pick a date that suits you; a longer one means fewer renewals, a shorter one means less harm if it leaks.

The Sync page

Open 🔄 Sync from the rail. The page is titled Sync with GitHub, and its card A token from GitHub has:

  • Make a new token on GitHub: opens GitHub's form for a new fine-grained token in your system's browser.
  • The two ways to set it up, from the table above, and make the repository on GitHub for the second.
  • Token: paste the token here.
  • This device, in commit messages: a name for this device, filled in for you (Mac, Windows, Linux, Android…). Change it to something you will recognise, such as laptop or phone.
  • Continue: checks the token with GitHub. While it does, the button says Checking….

Choose the repository

Once GitHub accepts the token, the page says "Signed in as you. Its modules go in one folder each." and shows Choose the repository:

  • The repositories the token can write to, each marked private or public, with Use. With more than eight, a Find box narrows the list.
  • Or one this list does not show: type owner/name (or paste its address from GitHub) and press Use.
  • A new repository: a Name (it suggests digidream-modules), a private tick, on by default, and Create. This needs a token for All repositories with Administration.
  • Branch (empty: the repository's own): leave it empty unless you know you want another branch.
  • Back returns to the token.

Once you pick or create one, you are connected, and every module on this device starts syncing.

Connected

The page now shows three cards:

  • The repository: its name (a link that opens it on GitHub) and branch, "Signed in as … This device: …", and Sync now, Change repository, Disconnect. If the repository is public, it says so: "The repository is public: anyone can read these modules."
  • On this device: each module with its state, a Sync button, and a sync tick. Untick a module to keep it off GitHub; it then says not synced.
  • On GitHub, not on this device: modules in the repository that this device does not have, each with Get (below). When there are none it says "Nothing: every module on GitHub is here too."

What syncs, and when

You don't press anything. The studio syncs a module:

  • when you open it;
  • a few seconds after a save (the studio saves as you edit);
  • when the app comes back to the front, for instance when you switch back to it on a phone;
  • every couple of minutes for the module you have open, to pick up another device's changes;
  • when you press Sync now or a module's Sync.

Each sync that has something to send is one commit. Its message names the module and the files, and the device: for example "my-level: maps/first.studio.json" and "From the studio on laptop."

In the repository each module is a folder named after its id, holding the module as the studio keeps it: module.studio.json (the module's settings), maps/ (one file per map), assets/ (imported pictures, sounds, fonts) and sources/ (texture, sprite, music and sound projects). Nothing baked is sent: the studio bakes again on each device. A file is only sent when its content changed.

Two devices

Each file is compared three ways: what this device has, what GitHub has, and what both had at the last sync. So the studio knows which side changed.

  • Changed on one side only: that side wins, quietly. Edit map first on your laptop and map cave on your phone, and after a sync both devices have both edits.
  • Changed on both sides in the same way: nothing to do.
  • Changed on both sides differently: a conflict. The studio never guesses; it asks.

When changes come in from GitHub to the module you have open, the studio first takes a snapshot of the module as it was (before sync from …), then reloads it in place: the same map and the same view. Undo starts afresh; the snapshot is your way back.

A conflict

The module's row on the Sync page opens a box: "Changed here and on GitHub since the last sync. Choose which to keep; the other stays in history (GitHub's commits, or the studio's Snapshots for this device's)." Each file is named as you know it (map first, module settings, textures/BRICK.png), with two choices: this device or GitHub. All this device's and All GitHub's choose for every file at once. Keep these finishes it.

The version you don't keep is not lost. If it was GitHub's, it is in the repository's history. If it was this device's, it is in 🕘 snapshots.

The choice is per file, and a map is one file. Two people (or two devices) working on different maps never conflict. Working on the same map in two places at once always will.

Getting a module onto this device

A module that is on GitHub but not here is listed under On GitHub, not on this device. Press Get: the studio brings it in, and from then on it syncs like the others. Open it from Home's other modules.

Every device starts with a module called My Level (its id is my-level), and you may have opened the same examples on both. These have the same id on each device, so they meet in the same folder on GitHub. The first sync on a new device compares them file by file: files that differ ask which to keep. If the other device has the work you want, choose All GitHub's.

Deleting

A delete is never copied across. If you delete a module on this device, its copy on GitHub stays, and it shows under On GitHub, not on this device again. If its folder is removed from GitHub, this device keeps its copy and offers Upload again, or you can untick sync.

Try it: a computer, then a phone

  1. On your computer, in the studio, open 🔄 Sync. Press make the repository on GitHub, sign in to GitHub if asked, and press Create repository on GitHub's form (it is already named digidream-modules and private).

  2. Back on the Sync page, press Make a new token on GitHub. Name it studio laptop, choose an expiration, choose Only select repositories and pick digidream-modules. Under Repository permissions, set Contents to Read and write. Generate it and copy it.

  3. Paste it into Token, set This device, in commit messages to laptop, and press Continue.

  4. Under Choose the repository, press Use beside digidream-modules. Wait until your modules say synced.

  5. Press the repository's name on the Sync page. GitHub opens: there is one folder per module, and the history shows a commit From the studio on laptop.

  6. Edit map first of My Level: move a corner. Within a few seconds Home's badge says syncing…, then synced.

  7. On your phone, in the studio, open 🔄 Sync. Make a second token the same way (call it studio phone), so each device has its own. Paste it, name the device phone, press Continue, then Use on the same repository.

  8. If My Level asks which to keep, choose All GitHub's and press Keep these. Open map first: the corner you moved on the laptop has moved here too.

  9. Under On GitHub, not on this device, press Get on any module the laptop has and the phone doesn't.

Changing repository, stopping, and the token

  • Change repository goes back to Choose the repository with the same token; Cancel leaves things as they were.
  • Disconnect asks "Disconnect from GitHub? The modules stay on this device and on GitHub; this device forgets the token." Nothing is deleted anywhere. To connect again, make or paste a token as the first time.
  • To keep one module off GitHub, untick its sync.
  • To turn the whole plugin off on this device, use its on switch on the Plugins page (Plugins).
  • To cut a device off for good, for instance a lost phone, revoke its token on GitHub: Settings → Developer settings → Personal access tokens → Fine-grained tokens, then delete that token. That device can no longer reach your repository. This is why one token per device helps.

Privacy

  • The token stays on the device where you pasted it, in the studio's own storage. It is sent only to GitHub.
  • A private repository is visible only to you (and anyone you invite on GitHub). A public one can be read by anyone, and the Sync page warns you when it is.
  • Never share a token. Anyone who has it can do on GitHub whatever you allowed it to. If you think one leaked, revoke it.

Plugins share the studio's storage, so a plugin you installed from someone else could read the token. Install only plugins you trust, and prefer a token for one repository only.

Signing in to GitHub from the apps with a button, instead of pasting a token, is not there yet. Neither is keeping the token in the system's keychain.

You edit map cave on your phone and map first on your laptop, then both sync. What happens?

  • The studio asks which device to keep
  • Both devices end up with both edits
  • The last device to sync wins, and the other edit is lost

Each map is its own file, and each was changed on one side only. Only a file changed on both sides asks.

In a conflict over map first you choose GitHub. Where is this device's version now?

  • Gone for good
  • In the repository, as a second copy of the map
  • In this device's 🕘 snapshots

Before the studio writes GitHub's version in, it takes a snapshot of the module, named before sync from …. GitHub's side, when you keep this device's, stays in the repository's history.

Your phone is stolen. How do you stop it reaching your modules on GitHub?

  • Revoke the phone's token on GitHub
  • Press Disconnect on your laptop
  • Make the repository public

Disconnect only makes the device you press it on forget its own token. Revoking on GitHub stops that token everywhere, which is why each device should have its own.
