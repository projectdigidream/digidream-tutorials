Graphs

A graph is Blueprint-style scripting: nodes joined by links. A map can carry graphs that run in its level, and the module can carry graphs that run once for the whole game. You draw them on a board, and the studio checks them as you draw.

This page tours the graph window. For graph scripting in depth (flow and data, variables, map logic, the game graph, debugging), follow the Graph scripting track. Every node is listed in Every graph node.

What a graph is

A graph uses the same words as trigger cards. Its events, conditions and actions are the trigger vocabulary's, run by the same code, so a door a graph opens is the same door a trigger opens. On top of that, a graph adds:

  • Flow: branch, sequence, delay, once.
  • Data: variables, literals, comparisons, arithmetic, logic and random numbers.
  • Plain nodes for common jobs, such as open_door, teleport, damage, play_sound or set_sky, which need no knowledge of the map's numbers.
  • Calls between a level's graphs and the game's.

Links come in two kinds:

  • Exec links say what happens next. The board draws them white.
  • Data links carry a value from one node to another. The board draws them green.

A run starts at a start node (a when … node) and follows the exec links node by node. A run is at most 256 steps, so a loop drawn by mistake cannot stall the game.

Try it: link and run

This toy board has four real nodes. when_button_pressed fires when a player presses a button (here use). once lets the run through the first time only. open_door raises a door, and play_sound plays a sound from an entity.

  1. Drag from then on when_button_pressed to in on once. While you drag, every input the link can reach lights up.

  2. Link once's then to open_door's in, and open_door's then to play_sound's in.

  3. Press ▶ run and watch the run follow the exec links. Press it again: once stops the second run.

  4. Drag the green entity pin of when_button_pressed to the entity pin of play_sound. This is a data link. Run again (after reset), and read what the sound now plays from.

  5. Drag when_button_pressed's then straight to open_door's in. The old link from then disappears, because an exec output goes to one place only.

Unlinked, play_sound's entity input is the event's own entity. Most nodes work this way: you only need a data link when you mean another entity, such as a monster that a spawn has just made.

Where graphs live: the Graphs section

Graphs, in the sidebar's Logic group, lists every graph of the module, in two groups:

  • the game's graphs, with + new graph for the game below them. A new module already has two: welcome, which shows the keys in the panel controls for ten seconds as the game starts, and death, the death screen (see What a new module holds).
  • One group per map, headed by the map's name, with + new graph on map.

Each row shows how many nodes the graph has, what it calls and what it answers. An empty graph says "empty -- not written until it has a node". A row also shows the graph's first problem, and if a graph calls a name that no graph answers, a warning says so below the list. Tap a row to open the graph. A map's graph opens with its map, because its places are picked on that map.

You can also open a map's graph from inside the map editor, with the Graph tool in its toolbar.

A map and the module can each hold as many graphs as you like: one for the doors, one for the shop, one for the boss. The name is the graph's identity, so names must be unique within a map, and within the game. A level's graph and a game graph may share a name, because they run in different places.

To do something in a level from the game's graph, such as move a lift, use a call node with to: level. It starts the on_call nodes of the same name in the graph of the level the entity is in. A level reaches the game the same way, with to: game.

The graph window

Along the top of the window:

  • The title: the map's name for a map's graph, or the game.
  • A list of this map's (or the game's) graphs, to switch between them. Its last entry, + new graph…, makes a new one.
  • + node…, which opens the node menu.
  • scene, once the graph has nodes (see Playing a scene).
  • A count of problems, in red, when there are any.
  • The way back: map for a map's graph, graphs for the game's.

On a phone, the bar also has tabs to switch between board, details and 𝑥 (the variables).

The board

  • Link: drag from a pin on the right of a node to one on the left of another. While you drag, every input the link can reach lights up.
  • Replace: an exec output goes to one place and a data input takes one value, so a new link replaces the one it would break. The board says so, naming the wire that went: "an exec output leads to one node: the wire from … to … was replaced (undo puts it back; for both, add a sequence)". One undo brings it back.
  • Zoom: pinch, use the wheel, or use the bar in the corner: −, the zoom level, +, and ⤢, which puts every node in view.
  • Delete a node: the small ✕ in its header deletes it and its links. Undo brings it back.

The node menu

+ node… opens a searchable menu. Type a word or two (fog, open, shop buy) and it narrows to the entries whose name, group or description has them all, names first. Each entry shows the first line of its description under its name, on lines of its own.

  • Enter adds the first match.
  • Esc closes the menu.

With nothing typed, it lists everything, by group:

Some groups have an icon before their name. A new node starts with sensible values: an option's first choice, a few seconds, the first monster. It goes to the nearest free spot beside the node you picked (or the others), by its real size, so it never lands on top of another node, and the view moves just enough to show it.

The side panel

Tap a node to edit it in the side panel. A node shows its main arguments on the board, and the rest are in the side panel. Every field has a help button that shows its own description, and so does the node's header.

  • Places are picked on the map. Tap a room for a sector or a tag, the floor for x/y/z, a placed thing for its name, or a wall for a side. The board steps aside while you tap.
  • Linked arguments: a field with a link into it reads ← node.pin, and asks for no value.
  • Optional arguments stay off the node until they have a value or a link. + N more… brings them on.
  • Names from the module: a sound, a panel, a cue, a movement state or a meter is offered from what the module has. play_sound's list has the module's sounds at once (it said (none) until the Sounds page had been opened).
  • delete node is at the bottom of a node's details.

Tap a link to pick it. Its panel has bend (with a plus before it), which adds a point the link is drawn through so you can route it round other nodes, and delete link.

Below every selection, the panel shows the graph itself: its name (renaming it here), + new graph and delete graph, which asks first.

Notes

a note (in the board group of the menu) is a labelled, coloured box on the board. If a node is picked, the note is placed round it.

  • Move it by its title: the title has a grip (✥) and says drag to move. Every node and bend inside moves with it.
  • Resize it by its handles. Its bottom-right corner always shows a grip; a picked note shows a handle on every side and corner, and the far side stays put while you drag.
  • Edit its text in place: tap the title twice, or its ✎. Enter keeps the new text, Esc puts the old one back.
  • Its text and colour are also in the side panel under note, which repeats these three ways of handling it. Its ✕ removes the note and leaves the nodes.

Notes and bends are only for the board. They are saved with the graph, and the game never runs them.

Variables

Open variables… in the side panel (on a phone, the 𝑥 tab). It lists two kinds of thing:

  • This graph's own variables. + variable asks for a name (letters, digits, underscore) and adds one starting at 0. Set its start value in starts at; it can be a number, a word, or true and false. A map's variables start again when the level does. The game's are kept from level to level.
  • Every property of an entity, such as hp, alive, x, y, z, speed, grounded, facing and is_player, plus all 50 movement rules. Each shows its type, whether a graph may set it, and what it is.

Each row has get, set and add buttons that drop the node onto the board. The get_var, set_var and add_var nodes choose their var from a dropdown that offers only what that node may use: set_var offers only settable ones, and add_var only settable numbers. Their entity input says whose property is meant. Unlinked, it is the event's entity.

A number from a variable

A numeric field that has a data input has a small 𝑥 beside it. Tap it, and the field becomes a choice of the graph's variables and the entity's numeric properties. ✕ makes it a typed number again. A few fields have no 𝑥, such as a sequence's count, because the engine cannot take them from a link.

A variable may not have a property's name. The studio refuses hp as a variable name, because the engine would refuse the graph.

Answering a key

Three nodes listen for buttons:

  • when_button_pressed fires once, on the tick a player's button goes down.
  • when_button_released fires on the tick it comes up.
  • button_held reads whether it is down.

Their button is a choice of the engine's buttons (jump, dash, grab, hover, fly, grapple, use, attack, alt_attack, crouch) and the module's own keys. The keyboard button beside it opens Controls, where you make those keys (see Controls). A button that nobody has is a problem, because the server would refuse the graph.

  1. In Controls, press + key. A key called action appears, waiting with press a key… (Esc): press T. Then rename it reload. (Avoid R: the engine uses it to turn the camera, and Controls warns about it.)

  2. Open Graphs and press + new graph on your map. Name it keys.

  3. Press + node…, type button pressed and press Enter. Set its button to reload.

  4. Add a play_sound node, pick a sound, and link the first node's then to its in.

  5. Back in Controls, rename the key to reload2. Reopen the graph: the node now says reload2, because a rename follows into every graph that answers the key.

How a player looks and moves

Three families of nodes in do to a thing act on a player:

  • How they look: set_avatar draws them with another avatar, set_layer draws a prop on them (armour, a weapon in hand) in their own animation, and set_animation_for plays one animation where another would play. See The world.
  • Their settings: change player setting sets, adds to or multiplies one of the player's settings (jump height, speed, ledge grab and the rest), for good or for some seconds. See How the player moves.
  • The module's movement: ask_movement_state, set_meter, start_move, enable_movement_state and enable_move, with start nodes in when … (when movement state entered, when meter empty and the rest). See How the player moves.

Playing a scene

The menu's cutscene group takes the controls and gives them back (start_cinematic, end_cinematic), shows lines at the bottom of the screen (subtitle, chained by their done exit), and fades.

A subtitle's mode is line (the whole line at once, the default) or typed: the line is typed out a few letters at a time, as in an old RPG. A typed line has three more fields: speed (letters a second, 30 by default), pack (letters that appear together each step, 2 by default) and sound, a sound played with every step that shows a letter (a step of spaces is silent; with none, it types in silence). Unless you set seconds, a typed line stays long enough to type it and then to read it.

camera flies a camera path (camera_flythrough), rides one while tracking the player (camera_track), follows again, or shakes. A path is chosen from the map's camera paths by tag.

scene plays the run from the picked node, or else from the first start that reaches a cutscene or camera node, over the map. It is timed as the game times it: the bars, the fade, each subtitle, the camera on its curve, the shakes. A typed subtitle is typed out in the preview with the game's own typewriter, sounding each step, and timed as the engine times it: its letters at its speed, then the reading time. Anything only the server does (a door, a call) appears as a line in the corner when it happens. Esc or ■ comes back.

See Camera and cinematics for drawing the paths.

In Gem Hollow: its graphs

Gem Hollow does all its logic with graphs, every one of them annotated with notes. Open Graphs: there is no game graph, one graph on menu and seven on world.

  1. Open Graphs and tap levers under world. The board opens on the map's graph, with each lever's nodes inside a note.

  2. Tap the red lever's open_door node. In the side panel its tag is 11: tap the field, then the red gate on the map.

  3. Drag the blue note by its title. Its nodes move with it. Pick it and drag its right side to widen it; then double-tap its title, change the text, and press Esc to put it back.

  4. Switch to intro in the bar's list. Tap the first subtitle, bring on mode from + N more… and set it to typed, with sound set to ui.select, a short blip from Gem Hollow's pack.

  5. Press scene. The flight plays over the map and your line types itself out. Press Esc to come back, and ⌘Z to undo the change.

  6. Open main under menu and find the quit_game node at the end of the Quit chain.

When the studio says no

The studio names what the engine would refuse while you draw: a button nobody has, a map the module lacks, a path tag the map does not have, a variable named like a property. The problems show in red in the side panel, as a count in the window's bar, and on Home. Play refuses to start while a graph has problems. The window's warnings also show on the board itself, by the node they are about.

It also warns about graphs that load but would not do what they look like.

  • An opening line that reaches nobody. A level starts before any player is in it, so a subtitle, a fade, a cutscene, a camera or a sound run from when level starts is seen by nobody. The board says so at the node, and suggests when player arrives, with a once for the first time only.
  • Removing the player. A script cannot remove a player, and the run stops there. After when prop touched, a despawn left at its default now removes the prop that was touched: its who? reads target -- the prop (default here). A remove with nothing linked takes the prop too. Where a despawn or a remove would still hit a player, the board says so in red.
  • A second wire from an exec output replaces the first, and the board names the wire that went (see The board).

What the game said, on the board

Some problems only show when the game runs: a name the server does not know, a node that failed. Back from Play, what the game said about a graph is on its board, at the node that failed: "in the last play-test, the game said: …". The line goes once you change that node, and at the next Play. The Play log has the same lines.

Scripts: the module's own Lua

Most behaviour is written in the studio's own words: triggers, monster brains, weapons and graphs. For anything they cannot say yet, Scripts holds the module's own Lua. A script there runs in every level, in its own scope, after the module's monsters are loaded. Hooks it defines (on_tick, on_attack …) run alongside every other script's, rather than replacing them.

  • + script asks for a file name (it suggests module_hooks.lua) and opens it.
  • Tap a script to edit it in the text box. Below it: rename and delete. Deleting asks first, because every map stops declaring it.
  • With the Code plugin on, a script also has edit in Code and open with…. Code is a Lua editor with line numbers, highlighting and blocks checked as you type. See Plugins.

What should run once for the whole game, not once per level, belongs in the game's graph, not in a script.

You want a score that survives from one level to the next. Where does the variable go?

  • In a map's graph, with + variable
  • In a graph under the game's graphs
  • In a script under Scripts

The game's graphs run once for the whole game, and their variables are kept from level to level and saved with the game. A map's variables start again with its level, and a script runs separately in every level.

when_button_pressed's then is linked to once. You drag a new link from the same then to open_door. What happens?

  • Both links stay, and the run goes to both nodes
  • The studio refuses the new link
  • The new link replaces the old one

An exec output goes to one place. To do several things in a row, chain them, or use a sequence node, whose exits run one after another.

A map's graph runs a subtitle from when level starts, and nobody sees it. What does the board suggest?

  • A longer seconds on the subtitle
  • Starting it from when player arrives, with a once for the first time only
  • Moving it to a script

The level starts before any player is in it, so what speaks to the players then reaches nobody. A player's arrival has a player to speak to.

In the node menu you type fog. What does Enter do?

  • Adds the first entry that matches
  • Closes the menu
  • Opens the fog settings of the picked room

Enter adds the first match; Esc closes the menu.
