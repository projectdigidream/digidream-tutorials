Plugins

Plugins are other editors that run inside the studio: ThreeSprite for sprites, qPainter for textures, DigidreamSound for sound packs, DigidreamSynth for music, Code for scripts, and two pages of their own: the Packager and GitHub sync. Each editor edits one of the module's files and hands it back when you return to the studio.

The studio's own pages that edit a kind of file count as editors too: the Scripts page, the Textures page, the Sounds page and the Monsters workshop. A plugin is offered beside them and never replaces them. Code, for example, has the lowest priority, so the Scripts page stays the default for a script until you choose Code.

edit in, and open with…

  • edit in plugin (with a pencil before it) opens the file in the first plugin that edits it.
  • open with… appears when more than one editor can open the file. It asks "Open name with…", lists the editors (the studio's own marked (the studio)), and remembers your choice on this device.

Inside a plugin: studio and ✕

A plugin opens over the whole studio. The studio draws one slim bar above it, the same for every plugin:

ButtonWhat it does
studio (with a back arrow before it)Back to the studio, saving; its tooltip says save, and back to the studio. The studio asks the plugin for its document. If nothing changed, nothing happens. Otherwise it checks the document and puts it in the module as one undo step. If the document is refused, the plugin stays open and the bar says why.
✕Back without saving; its tooltip says throw the changes away, and back to the studio. If there are changes, it asks first: keep editing or throw them away.

Between them, the bar names the plugin and the file, and says changed · saved when you go back while there are unsaved changes, saving…, or a problem.

Leaving any other way, by the rail or the phone's back button, asks: save and go, discard or stay.

Opening a file in a plugin is an address of its own, so reloading the page comes back to the plugin.

Plugins wear the studio's style. When you change the studio's style, mode or pointer (Settings → Look, or the Style card on Home), every bundled editor follows: its own colours, fonts and colour scheme are mapped onto the style's. A few canvases an editor paints in fixed colours, such as the DAW's lanes and waveforms, keep them. A plugin you write receives the style through the skin message if it asks for it (onSkin in the SDK).

Drafts

A phone often closes an app that is in the background. So while a plugin works, it sends the studio a draft every couple of seconds, and the studio also asks for one when the app goes to the background. Drafts are kept on the device, by file, not by plugin.

When you open a file that has a draft, the studio asks:

  • go on with it: open the draft, marked as unsaved work.
  • start from the saved one: throw the draft away and open the file as it was saved.

Back or discard clears the draft. Drafts that are left over are listed on the Plugins page.

  1. In your copy of Gem Hollow, open Textures, tap CRATE, and press edit in qPainter. qPainter opens in the studio's style.

  2. Paint a few pixels. The bar says changed · saved when you go back.

  3. Press ✕, then keep editing.

  4. Press studio. The texture's thumbnail shows your change.

  5. Press ⌘Z. The whole edit is undone in one step.

The Plugins page

Home's plugins (7) opens it. It shows:

  • + install a plugin (.dnpplugin) at the top.
  • A card per plugin: its name and version, bundled or installed, what it brings (edits …, bakes …, the … page, runs in the background), what it is allowed to do beyond that (a line starting may:, see below), and an on switch. An installed plugin also has uninstall.
  • Any plugin the studio refused, in red, with the reason: for example a plugin made for a newer studio.
  • opens in: for each kind of file with more than one editor, which one it opens in.
  • unsaved work: drafts left behind, each with open and throw away.

Installing a plugin

A plugin comes as a .dnpplugin file: a zip with a plugin.json at its root. Press + install a plugin (.dnpplugin) and pick the file. The studio checks the package first, then asks once, naming the plugin, its version, its author, what it brings and the permissions it asks for ("It asks to …").

A plugin runs inside the studio with the same access as the studio. It can read and change every module on the device. Install only plugins you trust.

Once installed, its editors are offered at once, and a rail page appears if it brings one. It is still there after a reload. The studio refuses a plugin that is older than, or the same version as, one it comes with.

uninstall deletes its files and reloads the studio. Unsaved work it left stays, for another editor to pick up. The on switch turns any plugin, bundled or installed, off on this device only.

Sources and baking

The module keeps the sources: the plugins' own project files, in sources/. The game cannot read those. Baking turns each source into the files the game loads, in assets/.

When it bakes

  • On the way back. studio with a texture or sprite bakes it at once, and the result is part of the same undo step.
  • Music is the exception. A track is baked at Play and Export, or by hand with bake now on the Music page, not every time you come back from DigidreamSynth.
  • Before Play and Export, the studio bakes every stale source: one whose bytes changed (an imported pack, say), whose baker changed version, or that was never baked. A source with no baker available stops Play and says which.

Bakes are cached on the device, so undoing an edit, or baking the same source again, costs nothing.

Duplicate and export

A texture's card (in Textures) and a sprite's card (in Sprites) have two more buttons:

  • duplicate copies every file it is made of under a new name (the first free NAME_2 is offered): a texture's picture, settings and qPainter project; a sprite's sheet, ThreeSprite project and bake record. The copy is a variant of its own, and its project bakes to the copy.
  • export PNG, export project, export .tsprite and export sheet send each file it has out of the studio (saved where you choose: on a phone, Android's save dialog asks where). An exported sheet is a .zip of its json and png, which can be imported again.

The Textures and Sprites tracks show them on Gem Hollow's own art.

Permissions, background services and badges

Most plugins only edit the file you hand them. A plugin that needs more says so in its plugin.json, and the studio shows it twice: in the install question, and on the plugin's card on the Plugins page, after may:. There are three kinds:

PermissionWhat the studio says
module-writereplace whole modules (any module here), as a sync does
backgroundkeep running in the background, whatever page is open
net:hosttalk to host, for example talk to api.github.com

A plugin with the background permission can bring a service: a hidden page that starts with the studio and runs all session, whatever page you are on. GitHub sync's service is what syncs your modules while you edit.

A plugin can also put a badge on a module: a coloured dot and a few words beside the version on Home, in Home's other modules list, and a dot on the module's item at the top of the rail. GitHub sync uses it to say whether the module is synced.

A permission says what a plugin means to do; it is not a wall. Any plugin runs with the studio's access. Install only plugins you trust.

Writing your own plugin

A plugin is a folder with a plugin.json and its pages. It can bring three things: editors (a page that edits one document and hands it back), bakers (a function from a source to what the game loads), and sections (a page in the rail). Here is the bundled Code plugin's manifest:

{
  "id": "code",
  "name": "Code",
  "version": "0.1.0",
  "protocol": 1,
  "suite": ">=0.1.0",
  "description": "A Lua editor for the module's own scripts: line numbers, highlighting, and blocks checked as you type. …",
  "editors": [
    { "id": "lua", "entry": "index.html", "kinds": ["record:script"], "label": "Code", "priority": 0 }
  ]
}
  • id, name, version, description: who it is.
  • protocol and suite: the editor protocol it speaks, and the studio versions it works with (>=x.y.z, ^x.y.z, an exact version, or *).
  • editors: each with an entry page, the kinds of document it edits (file:texture, file:tsprite, file:msproj, file:sfxproj, record:script, record:mob), a label, and a priority.
  • bakers and sections, when it has them. The Packager's manifest, for example, has one section: { "id": "package", "label": "Package", "icon": "section.package" }. A section's icon is an id from the studio's icon catalogue, such as section.package or section.sync, so every style draws it in its own look.
  • services and permissions, when it needs them. GitHub sync's manifest has one section, one service, and "permissions": ["module-write", "background", "net:api.github.com"]. A plugin with services must ask for background.

You've painted in qPainter for ten minutes and press ✕. What happens?

  • The texture is saved and the plugin closes
  • The studio asks whether to keep editing or throw the changes away
  • The changes are kept as a draft and the plugin closes without asking

✕ is discard. It asks first whenever there is anything to lose. studio is the way back that saves.

You edit a song in DigidreamSynth and press studio. When does the game's track change?

  • At once, as for a texture
  • Never, until you re-import the .mstk
  • At the next Play or Export, or when you press bake now

Music takes a while to bake, so it is baked at Play and Export (or by hand), not on every return.

Where can you install a .dnpplugin?

  • In the desktop app (Windows, macOS, Linux)
  • Everywhere, including Android
  • Only on Android

Installed plugins are served by a service worker, which the Android and iOS shells do not pass requests through yet. Bundled plugins work everywhere.
