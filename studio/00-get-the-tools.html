Get the tools

Everything in these tutorials runs in apps you download, and there's nothing to compile. Get Digidream Studio first: it includes the sprite, texture, sound and music editors, so for most people it is the only download.

Each tool is released on its own GitHub page. Choose the newest release, and take the file for your system:

  • Digidream Studio releases
  • ThreeSprite · qPainter · DigidreamSound · DigidreamSynth · Packager

The Downloads page of the Digidream website lists the same releases, every tool in one window.

Stable or development

There are two kinds of release:

  • Stable releases have a version of three numbers, such as 0.4.3. Most people want these.
  • Development releases have four, such as 0.4.3.1. They come between two stable ones and carry the newest features as each one is finished. GitHub marks them Pre-release. On the website's Downloads page, Nightly builds lists them, and each one is marked Nightly.

These tutorials teach the newest development studio. A feature that only the development releases have so far is marked with a badge naming the first release that has it, like this: studio 0.4.3.1. If your studio is stable, skip the parts with a badge, or take a development release.

Which kind you have decides which updates it is offered. A stable studio is only offered stable releases. A development studio is offered the newest release of either kind.

Install it

The apps are not signed by Microsoft or notarized by Apple yet, so the first launch shows a warning. The steps below get you past it once; after that, the app opens normally.

Windows

  1. Unzip Digidream Studio-windows-x64.zip: right-click it, Extract All…. Put the folder somewhere you keep apps.

  2. Open the folder and double-click Digidream Studio.exe.

  3. If Windows says "Windows protected your PC", click More info, then Run anyway.

macOS

  1. Double-click the .zip to unpack it, and drag Digidream Studio into Applications.

  2. Open it. The first time, macOS says "Apple could not verify…". Click Done.

  3. Open System Settings → Privacy & Security, scroll down to the message about Digidream Studio, and click Open Anyway. Confirm with your password. From then on it opens like any app.

Linux

  1. Unpack the archive: tar xzf "Digidream Studio-linux-x64.tar.gz", or open it with your file manager.

  2. In the Digidream Studio folder, run the launcher, the file without an extension next to the .png icon (it is currently named starter). From a terminal: ./starter.

Android

  1. Download the .apk on the phone or tablet, and tap it in your downloads.

  2. If Android asks, allow your browser or file manager to install unknown apps, then go back and tap Install.

  3. If Play Protect warns about an unknown developer, tap More details → Install anyway.

The studio is built for touch as well as a mouse. On a phone held upright there is no rail: Home is the list of sections. See Getting started.

On Android, the studio behaves as other apps do:

  • Back closes a dialog, or goes back to the page before; from a play-test, it goes back to the studio. On Home, where there is nothing further back, it puts the studio in the background instead of quitting it. When you return, you are where you left off.
  • The field you are typing in is lifted above the keyboard, so you can see what you type, and your next tap lands where you aim it.
  • A quick tap on a touch button in the game, such as FIRE, always counts, even on a slow phone.

These need studio 0.4.0 or later. If Back quits the app, update it.

Where your work is kept

  • Your modules live inside the app, on this device. There is no account and nothing is uploaded, unless you turn on Sync with GitHub, which keeps them in a GitHub repository of yours.
  • The studio asks the system to keep its storage (your modules, snapshots and drafts), so a phone that runs short of space does not clear it to make room.
  • The studio takes snapshots of a module as you work, and you can restore one from Home → snapshots.
  • To back up a module, or move it to another device, press export on Home. It saves the whole module as one pack file, and says what it saved. On the other device, import pack opens it.
  • The example projects, Gem Hollow and Cinderfall, come with the studio: Home → examples. Opening one makes a copy of your own, so you can't break the original.

Updating

The studio tells you when a newer one is out. It asks its releases on GitHub at most every six hours, and never gets in your way: offline, it just says nothing. When a later release exists, Home shows a card, "Studio 0.4.3 is out (you have 0.4.2)", with a short list of what changed and these buttons:

  • update now, where the studio can update itself (below).
  • download opens the release page in your system's browser, where you pick the download for your device.
  • not now hides the card until an even later release comes out.

Which releases are offered depends on your studio: a stable one is only offered stable releases (see Stable or development).

To ask straight away, press check for updates beside the version on Home (studio 0.4.3.1). It answers on the button itself: up to date (… is the latest), or could not check: … when GitHub could not be reached. If there is a newer release, the card appears.

update now

The studio updates itself. update now downloads the release for your device, puts it in place of this one, and starts it again. Everything you were editing is saved first, and your modules stay where they are.

  • Android installs the new studio over this one. The first time, Android asks to allow installs from the studio, and the button says allow installs, then press again: allow it, come back and press it again.
  • macOS, Windows and Linux download the release for your computer, and the studio quits and comes back as the new one.

While it works, a bar under update now shows how far it has got: downloading 12 of 80 MB (15%), then unpacking… (on a computer) or installing: Android takes it from here…, then restarting into the new one…. If something goes wrong, the bar goes and the button says update failed: … and why; press it to try again.

When it cannot replace itself, it says so. A Mac app opened straight from Downloads runs from a copy macOS will not let it change, and an install made by an administrator is not yours to replace. The button then says this app cannot replace itself where it is (move it to Applications, or a folder of yours); "download" gets it by hand. A studio unpacked loose among other files says, in the same way, the studio shares its folder with other files: unpack it into a folder of its own to update it here. Either way, download still works.

To update by hand, download the newer release and install it the same way, over the old one. Your modules stay: they belong to the app's storage on the device, not to the folder you unpacked. Export a pack first if you want to be safe.

If Home doesn't offer an example these tutorials mention, such as Cinderfall, your studio is older than the tutorials. Download the latest release.

You want to draw sprites and paint textures for your game. What do you download?

  • ThreeSprite and qPainter, then the studio
  • Just Digidream Studio: it includes both editors
  • The Packager

The studio opens ThreeSprite and qPainter itself, from its Sprites and Textures pages. The standalone apps are for working outside the studio.

macOS says "Apple could not verify…" and won't open the studio. What now?

  • Download it again: the file is damaged
  • Install the Intel version instead
  • System Settings → Privacy & Security → Open Anyway

The app is signed but not notarized by Apple, so macOS asks once. Open Anyway lets it run from then on.

Home says studio 0.4.3, and a development release, 0.4.3.1, is out. What does Home's card offer you?

  • Nothing: a stable studio is only offered stable releases
  • update now to 0.4.3.1
  • A choice between the two

A studio with three numbers is stable, and is only offered stable releases. To try the development one, download it from the releases page (Pre-release) or the website's Nightly builds.
